# 质量保障与黄金场景

每次修改都应至少覆盖以下用户场景：

| 场景 | 必须验证的结果 |
| --- | --- |
| 仅上传文献库、未给检索式/基准集 | 生成 HTML；21 项齐全；A/B/D3 等保持 `not_assessable`，不造值 |
| 离线运行 | 不发起网络请求；保留已有元数据；报告说明限制 |
| 已授权元数据补齐 | 不覆盖用户字段；失败不泄露凭据；输出可恢复缺口 |
| 多源候选发现 | 只有允许来源被调用；候选保持 `candidate_discovery` |
| HTML 人工筛选 | JSON/CSV 可导出；重复 ID、无理由的纳入/排除会被拒绝 |
| 两轮独立筛选 | 只有 `screened_complete` 记录能参与 B1/B2/B3 |
| 单篇评价 | 资格、方法学、可复核性、完整性和贡献分开；不输出跨研究设计的总质量分 |
| 输出安全 | HTML/JSON/manifest/输入快照均不含密钥或绝对路径 |

回归测试目录 `tests/` 覆盖上述核心约束。新增功能应增加最小正例、缺参反例和安全反例；发布前运行全部测试并审查生成的 HTML。
